## 2. 产品定位

- Minecraft 服务器通用菜单 UI 框架。
- 面向 Spigot / Paper / Folia / 插件模组混端（如 Mohist、Arclight 等混合端，尽力兼容）。
- 支持 1.18 至未来 26.x。
- 管理员通过 YAML 配置菜单，无需写代码。
- 其他插件开发者可通过 Java API / Kotlin DSL 注册菜单、动作、条件、数据源、主题。
- 菜单以容器界面（箱子等）呈现，提供现代化 UI 交互体验。
- 不使用客户端模组。
- 不依赖 NMS（服务端内部实现），只使用公开稳定 API。
- 服务端升级新版本时插件无需重写。

## 3. 功能需求清单

### 3.1 菜单定义与配置
- YAML 定义：标题、行数、布局、槽位绑定、装饰、按钮、内容区。
- 管理员零代码创建菜单。
- 热重载：修改 YAML 后无需重启服务端。

### 3.2 布局系统
- 支持不同行数的容器布局。
- 边框、按钮、内容区灵活摆放。
- 布局与内容解耦；同一布局可复用不同数据。

### 3.3 UI 渲染与主题
- 现代化视觉效果：渐变标题、渐变底色、玻璃材质。
- 不使用客户端模组。
- 支持资源包自定义物品模型、图标、纹理边框。
- 无资源包时，原版材质下也应美观可用。
- 主题系统：
  - 服主可设置全局默认主题。
  - 玩家可自选主题（命令或菜单操作）。
  - 主题包含配色、边框、图标、标题样式。

### 3.4 交互与动作系统
- 槽位点击触发动作链：多动作顺序执行，支持条件分支。
- 内置动作：
  - 执行玩家命令
  - 执行控制台命令
  - 给予物品 / 扣除物品
  - 打开菜单 / 关闭菜单
  - 切换页面
  - 发送消息 / 标题 / 声音
  - 切换主题
- 条件系统：
  - 权限
  - 资金
  - 持有物品
  - 服务器时间
  - 随机概率
  - 支持插件扩展条件
- 每个按钮可单独设置冷却时间，防连点刷动作。
- 点击反馈：声音、标题、字幕动画。

### 3.5 内容与数据
- 内容可来自 YAML 静态定义，或由其他插件通过 API 动态提供。
- 分页：内容超出一页自动生成多页。
- 搜索：菜单内搜索，异步执行，不阻塞服务端。
- 分类/筛选：按标签分类展示，可切换分类视图。
- 动态数据变更时界面自动更新。

### 3.6 性能指标
- 200 名玩家同时打开菜单时，服务端 TPS 不下降。
- 点击按钮到界面反馈 ≤ 100ms。
- 高网络延迟（200ms 以上）玩家操作依然流畅。
- 大量数据变化时界面刷新不造成卡顿。

### 3.7 版本与服务端兼容性
- 支持 Spigot / Paper / Folia。
- 支持 1.18 至未来 26.x。
- 服务端升级新版本时插件无需重写。
- 不依赖 NMS，使用公开稳定 API。
- 必须明确说明跨版本兼容策略。

### 3.8 外部依赖与集成
- 必须依赖两个核心外部插件，不可选择不装。
- 两个核心依赖由实现方选择，并说明理由。
- 除两个核心依赖外，其他集成均为可选：装了走对应接口，不装核心功能不受影响。
- 插件自身第三方库直接打包，不要求服主额外安装。
- 必须说明两个核心依赖的必要性设计。

### 3.9 命令与文本样式自定义
- 主命令简短易记，子命令结构清晰，减少玩家记忆负担。
- 所有玩家可见文本均可通过配置文件自定义：
  - 命令反馈消息的颜色和格式
  - 菜单标题颜色、按钮文字颜色
  - 提示、错误、成功消息的颜色
- 文本支持统一的颜色代码 / 占位符语法。

### 3.10 开发者 API
- 提供 Java API / Kotlin DSL。
- 其他插件可程序化定义菜单。
- 可扩展：注册自定义动作、条件、数据源、主题。
- API 稳定；大版本升级不破坏已开发插件的编译和运行。

### 3.11 演示菜单
- 商店页：分页 + 搜索 + 分类 + 购买按钮 + 冷却 + 动态余额显示。
- 玩家信息页：货币、等级、玩家状态等，演示占位符集成。
- 主题切换页：多主题预览与切换。

## 5. 技术决定（实现方）

- 构建：Maven 多模块；单一发行 jar 通过 shade 打包自身依赖。
- 编译基线：Spigot API 1.18.2（避免误用 Paper 独有 API），运行期特性探测。
- 不依赖 NMS / ProtocolLib / 数据包库。
- 调度抽象：Bukkit 调度器 / Folia Region、Entity、Async、Global 调度器。
- 文本引擎：自研 legacy/hex/gradient/MiniMessage 子集解析；不依赖 Adventure 作为硬依赖。
- 配置：Bukkit `YamlConfiguration`；逐文件校验，坏文件回退旧版本并报告。
- 数据持久化：YAML 玩家数据（主题、语言），异步防抖保存；冷却存内存。
- 经济：Vault API；占位符：PlaceholderAPI（异步缓存，避免阻塞）。
- UI 刷新：会话级脏标记 + 每 tick 合并刷新 + 物品差异更新。
- 搜索：Anvil 输入优先，聊天输入回退；过滤在受限异步线程池执行，结果回主/区域线程。
- API：`dev.bento.menu.api.v1` 稳定包，语义化版本；只做加法、接口默认方法、保留旧方法。
- Kotlin DSL：独立模块，编译进发行 jar，附带 Kotlin 标准库。
- 测试：单元测试 + 真实 Paper 1.18.2 / 1.21.11 / 26.1.2 / 26.3 + Folia 1.21.8 / 26.3 + Spigot 1.18.2 + 200 bot 压测 + 200ms 延迟代理测试。

## 6. 测试结论（最终）

- 单元测试：27 个，0 失败。
- 功能测试：Spigot 1.18.2、Paper 1.18.2、Paper 1.21.11、Paper 26.1.2、Folia 1.21.8 均通过菜单打开、分页、分类筛选、购买、冷却、搜索（铁砧/聊天回退）。
- Folia 26.3、Paper 26.3：启动与插件启用通过；mineflayer 不支持 26.3 协议，无法做 bot 级交互测试。
- 200 人分阶段基准（Paper 1.18.2，4 vCPU，200 mineflayer 客户端）：200 人在线且菜单全部打开、持续随机点击时 TPS 保持 20.0；插件平均点击处理 0.056ms、最大 3.3ms；平均渲染 3.7ms、最大 65ms。
- 200ms RTT 代理：菜单打开 RTT 220.5ms，点击到声音 217–220ms，符合“网络延迟 + 极低服务端处理”的预期。
- 已修复的缺陷：
  - Folia 调度反射错误导致菜单无法打开；
  - 铁砧输入使用自定义 holder 导致 `PrepareAnvilEvent` 不触发；
  - 点击路由误用 `event.getInventory()` 取到底部背包；
  - Vault 经济提供者晚于 BentoMenu 注册导致经济不可用；
  - PAPI 缓存 TTL 过期后周期刷新显示原始 `%token%`；
  - 1.18 单位测试中 `Theme.Builder` 默认物品导致无服务端 NPE；
  - 布局 11 个区域时 `Map.of` 抛异常；
  - 点击冷却与购买重复扣款/重复给物；
  - legacy hex 大小写不一致导致测试失败。
